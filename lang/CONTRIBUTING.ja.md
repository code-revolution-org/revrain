# コントリビューションガイド

revrain へのご協力に感謝します！バグ報告、ドキュメントの改善、コードの貢献を歓迎します。

revrain はギークと開発者のために作られた Hugo テーマです。ダーク基調のデザイン、デジタルレインアニメーション、ガラスモーフィズムのビジュアルを特徴とし、11 言語に対応、WCAG 2.2 AA アクセシビリティ基準に準拠しています。あなたの貢献はすべて貴重です。

## ブランチについて

このリポジトリには主に 2 つのブランチがあります：

- `main`：正式版 / 安定版。メンテナーが `dev` からのみマージしてリリースします。**直接の PR は受け付けていません。**
- `dev`：開発ブランチ。すべての機能・修正・ドキュメント変更は `dev` に提出してください。

> 重要：Pull Request を送る際、対象ブランチは必ず `dev` を選択してください。`main` ではありません。

## 貢献の方法

- バグの報告
- 新機能の提案
- ドキュメントの改善（`lang/` 配下の多言語 README 翻訳を含む）
- コードの修正や新機能の提出
- テストとフィードバックへの協力（特にさまざまなブラウザ、スクリーンリーダー、RTL 言語での動作確認）

## 開発環境

- Hugo >= 0.163.0（通常版で可。SCSS は外部の Dart Sass がコンパイル）
- Dart Sass（インストールして PATH に追加する必要あり。Hugo が自動的に呼び出します）

### ローカルプレビュー

```bash
cd exampleSite
hugo server
```

`exampleSite/hugo.toml` は `themesDir = "../../"` でテーマのルートを指しているため、追加設定なしで実行できます。本番ビルドはこちら：

```bash
cd exampleSite
hugo --minify --gc
```

## 問題の報告

Issue を立てる前に、同様の問題がすでにないか検索してください。

可能な限り以下を記載してください：

- 環境（OS、Hugo バージョン、ブラウザなど）
- 再現手順
- 期待する結果
- 実際の結果
- エラーログやスクリーンショット（あれば）

アクセシビリティ関連の問題（キーボード操作、スクリーンリーダー、コントラスト、RTL など）は、使用した支援技術とそのバージョンを明記してください。

## コードの提出

1. このリポジトリを Fork します。

2. Fork したリポジトリをクローンします：

   ```bash
   git clone https://github.com/あなたのユーザー名/revrain.git
   cd revrain
   ```

3. `dev` ブランチに切り替えます：

   ```bash
   git checkout dev
   git pull origin dev
   ```

4. `dev` からブランチを作成します：

   ```bash
   git checkout -b fix/問題の説明
   ```

   ブランチ名の推奨：

   - `feat/新機能`
   - `fix/問題の修正`
   - `docs/ドキュメント更新`

5. コードを変更してコミットします：

   ```bash
   git add .
   git commit -m "fix: ある問題を修正"
   ```

6. Fork にプッシュします：

   ```bash
   git push origin fix/問題の説明
   ```

7. GitHub で Pull Request を作成します。

   **PR の対象ブランチは必ず `dev` にしてください。`main` ではありません。**

## Pull Request の要件

- 対象ブランチ：`dev`
- 1 つの PR は原則 1 つの作業に絞る
- 何を、なぜ、どうテストしたかを説明する
- 大きな変更は先に Issue で議論することを推奨
- 無関係なフォーマット変更や大規模な変更を含めない
- パスワード、シークレット、個人情報をコミットしない
- テーマの動作を変更した場合は `README.md` を同期更新する（必要に応じて `lang/` 配下の多言語ドキュメントも）
- スタイルやスクリプトを変更した後は `hugo server` でローカル検証し、狭い画面（モバイル）でも正常に表示されることを確認する
- UI 操作を追加・変更する場合は、既存のアクセシビリティ慣行を維持する：キーボード操作可能、可視フォーカス、`aria-*` ラベル、`prefers-reduced-motion` 対応

## コミットメッセージの推奨

推奨ですが必須ではありません（既存のコミットスタイルを維持してください）：

- `feat: 新機能`
- `fix: バグ修正`
- `docs: ドキュメント更新`
- `test: テスト関連`
- `refactor: リファクタリング`
- `chore: 雑務`

## メンテナーによるリリースフロー

通常の開発はすべて `dev` で行います。
`dev` がテストで安定した後、メンテナーが `main` にマージし、正式版としてリリースします。
