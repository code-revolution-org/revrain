# Руководство по участию

Спасибо за интерес к проекту revrain! Мы приветствуем сообщения об ошибках, улучшения документации и вклад в код.

revrain — это тема Hugo, созданная для гиков и разработчиков: тёмный дизайн с анимацией цифрового дождя, эстетика матового стекла (glassmorphism), поддержка 11 языков и соответствие стандарту доступности WCAG 2.2 AA. Каждый ваш вклад ценен.

## Ветки

В этом репозитории есть две основные ветки:

- `main`: стабильная / официальная версия. Мержится и публикуется только мейнтейнерами из `dev`. **Прямые PR не принимаются.**
- `dev`: ветка разработки. Все функции, исправления и изменения документации должны отправляться в `dev`.

> Важно: при открытии Pull Request выбирайте `dev` в качестве целевой ветки, а не `main`.

## Как вы можете помочь

- Сообщать об ошибках
- Предлагать новые функции
- Улучшать документацию (включая многоязычные переводы README в `lang/`)
- Отправлять исправления кода или новые функции
- Помогать с тестированием и обратной связью (особенно в разных браузерах, программах чтения с экрана и RTL-языках)

## Среда разработки

- Hugo >= 0.163.0 (любая редакция; SCSS компилируется внешним Dart Sass)
- Dart Sass (должен быть установлен и находиться в PATH; Hugo вызывает его автоматически)

### Локальный предпросмотр

```bash
cd exampleSite
hugo server
```

`exampleSite/hugo.toml` уже указывает на корень темы через `themesDir = "../../"`, дополнительная настройка не нужна. Для сборки production-версии:

```bash
cd exampleSite
hugo --minify --gc
```

## Сообщение об ошибках

Прежде чем открыть Issue, поищите, нет ли уже похожей проблемы.

По возможности укажите:

- Ваше окружение (ОС, версия Hugo, браузер и т. д.)
- Шаги воспроизведения
- Ожидаемый результат
- Фактический результат
- Журналы ошибок или скриншоты (если есть)

Для проблем, связанных с доступностью (навигация с клавиатуры, программы чтения с экрана, контраст, RTL и т. д.), укажите используемую вспомогательную технологию и её версию.

## Отправка кода

1. Сделайте форк этого репозитория.

2. Клонируйте ваш форк:

   ```bash
   git clone https://github.com/ваше-имя-пользователя/revrain.git
   cd revrain
   ```

3. Переключитесь на ветку `dev`:

   ```bash
   git checkout dev
   git pull origin dev
   ```

4. Создайте свою ветку от `dev`:

   ```bash
   git checkout -b fix/описание-проблемы
   ```

   Рекомендуемые имена веток:

   - `feat/новая-функция`
   - `fix/исправление`
   - `docs/обновление-документации`

5. Внесите изменения и сделайте коммит:

   ```bash
   git add .
   git commit -m "fix: исправляет конкретную проблему"
   ```

6. Отправьте изменения в ваш форк:

   ```bash
   git push origin fix/описание-проблемы
   ```

7. Откройте Pull Request на GitHub.

   **Целевая ветка PR должна быть `dev`, а не `main`.**

## Требования к Pull Request

- Целевая ветка: `dev`
- Один PR должен делать по возможности одно дело
- Опишите, что изменено, почему и как это тестировалось
- Для крупных изменений сначала откройте Issue для обсуждения
- Не включайте несвязанное форматирование или масштабные изменения
- Не коммитьте пароли, ключи и личную информацию
- При изменении поведения темы обновите `README.md` (и при необходимости многоязычные документы в `lang/`)
- После изменения стилей или скриптов проверьте локально с помощью `hugo server` и убедитесь в корректном отображении на узких (мобильных) экранах
- При добавлении или изменении UI-взаимодействий соблюдайте существующие соглашения о доступности: управление с клавиатуры, видимый фокус, атрибуты `aria-*` и поддержка `prefers-reduced-motion`

## Рекомендации по сообщениям коммитов

Рекомендуется, но не обязательно (сохраняйте существующий стиль коммитов):

- `feat: новая функция`
- `fix: исправление ошибки`
- `docs: обновление документации`
- `test: тесты`
- `refactor: рефакторинг`
- `chore: прочее`

## Процесс релиза мейнтейнеров

Обычная разработка ведётся в `dev`.
Когда `dev` станет стабильным после тестирования, мейнтейнеры вливают его в `main` и публикуют официальную версию.
