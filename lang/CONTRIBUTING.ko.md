# 기여 가이드

revrain에 기여해 주셔서 감사합니다! 버그 보고, 문서 개선, 코드 기여를 환영합니다.

revrain은 개발자와 극(極)커를 위해 만들어진 Hugo 테마입니다. 다크 톤 디자인, 디지털 레인 애니메이션, 글라스모피즘 비주얼을 특징으로 하며, 11개 언어를 지원하고 WCAG 2.2 AA 접근성 표준을 준수합니다. 여러분의 모든 기여는 소중합니다.

## 브랜치 안내

이 저장소에는 주로 두 개의 브랜치가 있습니다:

- `main`: 정식 버전 / 안정 버전. 유지보수자가 `dev`에서만 병합하여 릴리스합니다. **직접 PR은 받지 않습니다.**
- `dev`: 개발 브랜치. 모든 기능, 수정, 문서 변경은 `dev`로 제출해 주세요.

> 중요: Pull Request를 제출할 때 대상 브랜치는 반드시 `dev`를 선택하세요. `main`이 아닙니다.

## 기여 방법

- 버그 보고
- 새 기능 제안
- 문서 개선(`lang/` 아래의 다국어 README 번역 포함)
- 코드 수정 또는 새 기능 제출
- 테스트 및 피드백 지원(특히 다양한 브라우저, 화면 읽기 프로그램, RTL 언어에서의 동작 확인)

## 개발 환경

- Hugo >= 0.163.0(일반 버전 가능. SCSS는 외부 Dart Sass가 컴파일)
- Dart Sass(설치 후 PATH에 추가해야 하며, Hugo가 자동으로 호출)

### 로컬 미리보기

```bash
cd exampleSite
hugo server
```

`exampleSite/hugo.toml`은 `themesDir = "../../"`로 테마 루트를 가리키므로 추가 설정 없이 실행할 수 있습니다. 프로덕션 빌드는 다음과 같습니다:

```bash
cd exampleSite
hugo --minify --gc
```

## 문제 보고

Issue를 제출하기 전에 비슷한 문제가 이미 있는지 검색해 주세요.

가능한 한 다음을 제공해 주세요:

- 환경(OS, Hugo 버전, 브라우저 등)
- 재현 단계
- 기대 결과
- 실제 결과
- 오류 로그 또는 스크린샷(있는 경우)

접근성 관련 문제(키보드 탐색, 화면 읽기 프로그램, 대비, RTL 등)는 사용한 보조 기술과 버전을 명시해 주세요.

## 코드 제출

1. 이 저장소를 Fork합니다.

2. Fork한 저장소를 클론합니다:

   ```bash
   git clone https://github.com/사용자이름/revrain.git
   cd revrain
   ```

3. `dev` 브랜치로 전환합니다:

   ```bash
   git checkout dev
   git pull origin dev
   ```

4. `dev`에서 브랜치를 만듭니다:

   ```bash
   git checkout -b fix/문제설명
   ```

   브랜치 이름 권장:

   - `feat/새기능`
   - `fix/문제수정`
   - `docs/문서업데이트`

5. 코드를 수정하고 커밋합니다:

   ```bash
   git add .
   git commit -m "fix: 특정 문제를 수정"
   ```

6. Fork에 푸시합니다:

   ```bash
   git push origin fix/문제설명
   ```

7. GitHub에서 Pull Request를 생성합니다.

   **PR 대상 브랜치는 반드시 `dev`여야 합니다. `main`이 아닙니다.**

## Pull Request 요구 사항

- 대상 브랜치: `dev`
- 하나의 PR은 가능하면 하나의 작업만
- 무엇을, 왜, 어떻게 테스트했는지 설명
- 큰 변경은 먼저 Issue로 논의 권장
- 관련 없는 포맷팅이나 대규모 변경은 포함하지 말 것
- 비밀번호, 키, 개인정보를 커밋하지 말 것
- 테마 동작을 변경할 때는 `README.md`를 함께 업데이트(필요 시 `lang/` 아래의 다국어 문서도)
- 스타일이나 스크립트를 수정한 후에는 `hugo server`로 로컬 검증하고 좁은 화면(모바일)에서도 정상 표시되는지 확인
- UI 인터랙션을 추가·변경할 때는 기존 접근성 규칙을 유지: 키보드 조작 가능, 가시 포커스, `aria-*` 라벨, `prefers-reduced-motion` 지원

## 커밋 메시지 권장

권장 사항이지만 필수는 아닙니다(기존 커밋 스타일 유지):

- `feat: 새 기능`
- `fix: 버그 수정`
- `docs: 문서 업데이트`
- `test: 테스트 관련`
- `refactor: 리팩터링`
- `chore: 잡다한 작업`

## 유지보수자 릴리스 프로세스

일반 개발은 모두 `dev`에서 진행합니다.
`dev`가 테스트로 안정되면 유지보수자가 `main`으로 병합하여 정식 버전으로 릴리스합니다.
